# Audit synthesis — job-hunt skill, HEAD 9809599

## Verdict

The skill is sound in its architecture and unsound in three specific mechanisms it treats as load-bearing. Eight lenses ran ~200 mutations against it; the gate layer is genuinely strong (154/174 finding branches die when neutered, 167/171 quiet cases are pinned, the mode-file hash backstop works in all four modes, the discover provenance core is real), and no lens found a gate whose trigger condition is unreachable. The weakness is uniformly at the *composition* seams: `check_apply` will sign off on a package while two of its own gates sit three lines above in `journal.jsonl` with `verdict: fail`; `check_claims` compares against raw file bytes rather than parsed fields; `count_coverage` prints two invented pessimistic facts as assessed data; and `render_cv` silently deletes every codepoint above U+00FF from the one artifact a recruiter reads. Nothing here should stop you using it on your own NL/EN MRI applications today — but do not let it render a PDF containing a name, employer or institution with a diacritic until item 2 is fixed, and do not read `check_apply` exit 0 as "the package is gated" until item 1 is fixed.

## What survived refutation

Ranked by damage. Damage = wrong artifact leaves the building > silent gate bypass > loud-but-wrong.

### 1. `render_cv` silently drops every character above U+00FF from the PDF
*Converged: robustness-inputs (found), its refuter (widened it from "exotic scripts" to Latin Extended-A).*
`find_latex_engine` prefers tectonic (XeTeX-based) and `modes/apply.md:80` tells you to install it, but the preamble is pdfLaTeX's `inputenc`+`fontenc` because `_has_cjk` (render_cv.py:941) only recognises U+3000–U+9FFF, Hangul and Thai. `Łukasz Wójcik / Politechnika Śląska / Škoda / Ștefan` render as `ukasz Wójcik / Politechnika lska`. `render_pdf` runs `subprocess.run(..., capture_output=True)` and throws away 234 `Missing character` warnings; exit 0; `Wrote cv.pdf`.
**Why nothing reports it:** `check_pages` reads the PDF for a page tree, not glyphs. The judges read `cv.md`, which is intact. `render_cv` writes no receipt at all. And `test_render_cv.py:130` — docstring *"for UTF-8 safety"* — **pins the broken preamble**; the only two `render_pdf` tests monkeypatch the engine away, so no test ever compiles a real PDF.
**Fix:** engine-aware preamble (fontspec + `\setmainfont` when tectonic/xelatex/lualatex, keep T1+inputenc only for pdflatex); threshold `ord(ch) > 0xFF`, not a second script range; scan the captured engine output for `Missing character` and fail; add a PDF-text-coverage assertion to `check_pages` (it already holds a receipt and opens the file) requiring `meta.name` and each `experience[].org` to appear in the extracted text.

### 2. `check_apply` exits 0 on a package whose gates failed or never ran
*Converged: dead-gates, cross-layer, robustness-inputs, spec-conformance, generalization-user. Five lenses, three independent mechanisms, all STAND.*
- `PASSING_VERDICTS = ("pass", "recorded")` (confirmed, check_apply.py:47) and both `check_claims --record` and `check_render_freshness --record` write `"recorded"` as *setup*. A workspace that ran only the documented mode-entry setup and never ran the verification pass exits 0 — and a later `--record` on resume **erases a real prior failure**, because `receipts[-1]` wins. No gate in `REQUIRED_GATES` ever writes `"recorded"` as a clean-check verdict, so the token buys nothing.
- `REQUIRED_GATES` is five names. `check_pages` and `check_word_limits` are not in it, and their trigger conditions (`cv.pdf` exists; `application_type: structured`) are exactly as visible as the `letter.yaml` condition already handled at line 88.
- Worse than any lens filed: the gates do not have to be *skipped*. They can run, print `OVER_LIMIT`/`CV_TOO_LONG`, write `verdict: fail`, and `check_apply` writes its own `pass` three lines below in the same file.
**Why nothing reports it:** `_good_workspace` in `test_check_apply.py` forges all five receipts with `journal.receipt(..., "pass")` and never invokes a real gate, so record-vs-verify never enters a fixture; patching `PASSING_VERDICTS` to `("pass",)` leaves 793/793 green. `test_skill_structure.py:70` asserts each script name appears *somewhere* in the self-check, never under which heading. And SKILL.md:684's heading claims all ten are required, which converts "I skipped it" into "check_apply covered it". For structured applications this is the whole ballgame: `references/structured-applications.md:52` routes all three judges away from the supporting statement, so `check_word_limits` is the *only* reader of the artifact that is actually scored.
**Fix:** `PASSING_VERDICTS = ("pass",)` in check_apply only (leave check_assessment's alone — `recorded` is legitimate for its reporter upstreams). Add a general rule: fail on **any** receipt in the journal whose latest verdict is `fail`, not only named ones. Key `check_pages` on `cv.pdf` **and** `tailored-profile.yaml` (both are its inputs; `could_not_run` is not passing) and `check_word_limits` on the statement file, not on a `posting.yaml` proxy. Give the `--record` paths a distinct verdict *or* discriminate on `inputs` (works for check_claims — record names `profile.yaml`, verify names `tailored-profile.yaml`; does **not** work for check_render_freshness, whose two receipts are identical, so that one needs the verdict split). New code `NOT_VERIFIED`, not `UPSTREAM_FAILED` — "failed" is the wrong diagnosis for "never ran". Split SKILL.md:684 into required/not-required and pin the partition against `REQUIRED_GATES` in a test. Also fix `test_check_pages.py:99`, whose docstring states the false claim as fact.

### 3. `check_claims` sources a claim by raw substring over the whole master file
*Converged: dead-gates, honesty-mechanisms, end-to-end (its refuter found the cleanest case). Same root cause, three lenses.*
`check_claims.py:193` — `if len(key) < 2 or key in master_text` where `master_text` is the entire `profile.yaml` flattened. Confirmed passing: `Go` sourced by `django`/`algorithms`; `Java` by `JavaScript`; `MSc` (certification) by the degree `MSc Computer Science`; `PhD` by a **YAML comment** in the shipped `assets/profile.example.yaml`; `Dutch` from master `Dutch (B1)`; `AI` from the word `email`, permanently, in every profile using the canonical schema. The docstring says the opposite: *"each is a string that compares exactly."* Separately, scope: `experience[].title` is scanned and `experience[].org` — the adjacent key in the same dict — is not; nor are `education[].institution`, `publications`, `awards`, `projects[].role`, `volunteer`, `achievements`, `board`. A fabricated employer, institution or Nature paper passes. (Bullets/summary being out of scope **is** recorded and defensible — see dropped.)
**Why nothing reports it:** `test_a_term_the_master_mentions_only_in_a_bullet_is_sourced` is a legitimate cry-wolf guard and reads as if it *requires* whole-file substring. It does not: I confirmed a word-boundary patch keeps it green and the full suite at 795. **Fix:** parse the master with `yaml.safe_load` and build the permitted set from **leaves** plus a word-boundary token index over prose leaves — this is what kills the YAML-comment class, which a boundary match alone does not. Exclude `contact.links` and `projects[].links`. Add `QUALIFIER_STRIPPED` narrowly (trailing status parenthetical only — `(in progress|expired|B1|planned|expected)`; "any substring relation" fires on the honest de-escalation `Senior ML Engineer` → `ML Engineer`). Extend scope to the seven unscanned atomic families, and make the omission unrepeatable with a **field-path**-granular registry test against `full_profile.yaml` — section-granular would re-certify `org`. Reject dead-gates' token-sublist fix: `_PUNCT` preserves `.` `-` `/`, so `pytorch.` and `c++/cuda.` cry wolf on honest master bullets.

### 8. The interview write-backs are shape-checked, never meaning-checked
*interview-mode, three STANDS.*
`check_walkback` resolves an `UNSOURCED-FACT` if any promoted `claims.yaml` row's `term` is a case-insensitive substring of the quote — one row with `term: "on"` discharges every unsourced fact in the round. `retracted` is required to be *present* and its value is never read, so an explicitly withdrawn claim still resolves — and `claims.yaml` is append-only with retraction-by-marking, so retracted rows accumulate by design. `check_claims.py:197` implements the opposite semantics for the same file. The `#Q<n>` fragment in `source_ref` is ignored entirely (only `transcript_name in source_ref`), so an ordinary clerical `#Q2`→`#Q1` still resolves. Separately, `quote_is_in` searches the whole transcript as one flat string, so an assessor can quote the **interviewer's own question**, tag it as the candidate's defect, and build a walk-back entry out of it — and `ref=` is checked for heading membership, never for containment. And every scraped-material rule (`WRONG_COUNTRY`, `STALE_SPECIFIC`, id, timestamp) sits behind `if source != 'scraped'`, so `source: generated` skips all of them in one token, while `modes/interview.md:65` positively teaches a distinction that makes the mislabel a *good-faith* outcome.
**Fix:** term floor ≥4 (`PACS` in the fixture is exactly 4) + `\b` boundary + skip retracted rows with a `PROMOTION_RETRACTED` finding; speaker-aware per-question haystacks with a `NO_SPEAKER_LABELS` code first (persona-named turns like `**Sanne:**` otherwise produce eight correct-quote false positives with the wrong diagnosis); define in `modes/interview.md` which label a post-derived question takes, then require `mock/raw/` captures and `SCRAPED_NO_CAPTURE`/`UNDECLARED_SCRAPE`. Two sub-fixes to drop: `SHAPE_ROW_ASKED` (no script reads `asked` at all, and the fixture's one scraped row has `asked: false`), and `(today - when).days < 0` for future stamps (nowcoder stamps are UTC+8 — needs a ≥2-day tolerance or it fires on the freshest posts).
