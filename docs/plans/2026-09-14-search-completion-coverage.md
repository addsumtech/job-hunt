# 检索完成条件修复

用户已确认修复“查到18条就结束”的问题。数量目标、来源读取预算和检索完成是三个不同概念。本次不改变网站读取上限，也不启动新一轮求职检索。

采用检索前登记范围、检索后核对进度、交付时重新执行检查的方案。单纯再补规则文字不能阻止旧故障；强制一个更大的岗位数仍会漏查或诱导凑数，因此不采用。范围列明来源和业务方向；每个来源与方向都需要处理结果及可核验的抓取证据。范围只能增补，不能查完后删掉未完成来源。已抓取但未入选的岗位需要明确排除或受阻记录。

新增检查独立于单轮 shortlist 检查，完整 discover/collection 报告在复制任何文件前必须通过；直接调用交付函数也不能跳过。转换工作模式不消除既有检索责任。用户明确要求的初步交付保留现有例外，不能由模型自行降级。访问受限须有同来源失败证据，且限制说明出现在报告；数量、配额、时间耗尽不属于访问失败。

验证包含：未登记范围、事后登记或删减范围、漏来源/方向、只写数量不足、达到目标但留有线索、伪造或改动证据、错引来源、未说明限制、跨轮/切模式/直接API绕过。正例涵盖完整覆盖、真实受限且其余来源完成、明确初步交付。用原18条案例验证旧式结果不能再自动通过新检查；不为历史检索补造事前登记。

这项检查证明已声明范围的处理完整性，不证明世界上不存在其他雇主或未记录的网页内容。来源选择和对正文的判断仍需诚实执行，并在检索前向用户说明范围。
