# job-hunt 设计文档

日期：2026-08-09
状态：已定稿，待实施

---

## 1. 目标

一个 Claude Code / Codex 双 runtime 共用的求职 skill，四个模式：

```
discover  →  assess  →  apply  →  interview
找什么       该不该投    怎么投     怎么答
```

它吸收现有的 `~/.claude/skills/job-application`（作为 `apply` 模式）和
`~/.codex/skills/job-search-coach`（作为发现与评估的教条来源），两者退役。

**不做的事**：不预测面试概率或录用概率；不代替用户在任何平台上写入；不替代法律、
移民或财务顾问。

## 2. 决策记录

每条都是本次对话中拍板的，附理由。理由比结论更重要——它决定了遇到文档没枚举的情况时怎么推广。

| # | 决策 | 理由 |
|---|---|---|
| D1 | **一个 skill，吸收式合并**，不是三个兄弟 skill | 三个 skill 的 description 会互抢触发，用户得知道喊哪个；评估逻辑会在两处重复。 |
| D2 | **不输出任何概率或 0–100 分** | 「面试概率 45–65%」背后没有任何数据，它就是个编的数。加权总分同样是假精度——`job-search-coach` 的 rubric 自己开头写着「不要制造假精度」，紧接着给了六个权重。 |
| D3 | 排序改用**序数档位 + 确定性规则**，且**全流程只有一套档位词表** | 合并 met/partial/missing 成一个数需要给 partial 一个权重，而任何权重都是编的。同时废除单独的 A/B/C/D 优先级：两套词表会给用户两个可能互相打架的结论。排序 = 按投递建议档位排，同档内按「可补缺口所需投入」排。**修订说明**：这一条推翻了本次对话早期「A/B/C/D 由脚本从档位推出」的说法——保留两套词表就得解释它们何时不一致，而那是没有正确答案的解释。 |
| D4 | 通用 skill，双语，**但先把中国和荷兰/西欧调深** | 其余市场诚实返回「本市场无惯例数据」，而不是拿通用建议冒充。 |
| D5 | 发现层**以 opencli 为主**，绿层 API 为降级路径 | 用户在被告知与自己 source-policy 冲突后重申了此选择。见 D6。 |
| D6 | **source-policy 同步改写成一套标准** | 不能留一份自己违反的政策文件。翻页与取详情从「红线」降级为**带硬上限的黄层行为**；红线保留在：绕验证码/风控、代理与指纹伪装、多账号轮换、后台无人值守运行、批量投递/打招呼、以及「没有新鲜来源信号就声称岗位还开着」。 |
| D7 | **完全只读**，无任何写操作 | 不设「确认后再发送」流程——一个确认流程本质上就是一条带减速带的写路径。机制：`access: read` 允许名单 + `check_no_write.py` 扫 journal。 |
| D8 | 一个仓库，**同时软链到两个 runtime** | 与用户的 slide-maker 一致。教条只保一份，不会漂。 |
| D9 | **discover 不自动串 apply** | 搜到 30 个岗位不自动生成 30 份 CV。shortlist 分档的意义就是让人做选择，自动串联会把一句「看看有什么」变成一小时的 token 燃烧。 |
| D10 | **assess 独立成模式** | 「这个岗位我该不该投」是最高频用法，现有 skill 做不到——它的评估只是改写的副产品。 |
| D11 | **引入 layer 1.5：`modes/*.md` 强制加载** | 见 §4.2。 |
| D12 | 名字叫 **`job-hunt`** | 不叫 `job-search`：用户已有 `job-search-agent` 和 `job-search-coach`，同名会混。 |
| D13 | 模拟面试**对话式实战**，四种轮次全上，结束落复盘 | 用户选择。四轮次 = 行为/经历深挖、技术/领域深度、系统设计/方案设计、HR/薪资/动机。 |
| D14 | 市场识别**直接问用户**，不做地名匹配器 | marketfit 的 `resolveMarket` 有 1000+ 行，其文档自己记了三类需要真正地名库才能关闭的缺陷；而市场卡是全套里唯一无源可引的断言，认错市场看起来和认对一模一样。问一句就把整类缺陷删掉。 |

## 4. 架构

### 4.1 仓库与安装

```
~/code_project/job-hunt/            ← 仓库根即 skill
  ├─ symlink → ~/.claude/skills/job-hunt
  └─ symlink → ~/.codex/skills/job-hunt
```

原 `job-application` 仓库保留作归档，不删。

### 4.2 分层（D11）

- **SKILL.md（layer 1）** —— 只放**跨模式绑定**的内容。每次触发都加载。估 320–420 行。
- **`modes/{discover,assess,apply,interview}.md`（layer 1.5）** —— 进入该模式即**强制加载**，每次只加载一个。
- **`references/*.md`（layer 2）** —— 按条件加载，每个都必须有一个**读文件之前就能判定**的触发条件，以及一个具名 backstop。
- **`scripts/`（layer 3）** —— 程序能判定的一律进这里。

**为什么 layer 1.5 不是又一次 slides_maker 式的回归**：那次回归发生在**可选且有条件**的 reference 上——模型读了 10 个里的 3 个，用错 helper 用错参数，还通过了所有自动闸门。模式文件不同：

1. 进入该模式后它是**无条件的**，不需要模型判断「是否相关」；
2. 一共只有四个，选择是**确定性的**；
3. 它有**两种 backstop 同时上**——模式的闸门脚本要求只在该文件里定义的产物字段，且 `journal.jsonl` 必须记录该文件的内容哈希。

回退方案：单体 SKILL.md，承担全量加载成本。

### 4.3 共享脊柱

```
~/.claude/job-profiles/<name>/
  profile.yaml              主档案 · 唯一真相源 · 任何模式都不可改
  search-preferences.yaml   目标市场/城市/职级/工作模式/语言/薪资底线/avoid-list/经验轨道
  answer-bank.md            跨投递累积的回答素材（唯一跨投递对象）

  searches/<YYYY-MM-DD>-<slug>/
    brief.yaml                SearchBrief
    shortlist.yaml            结构化 shortlist
    shortlist.md              可读版：§0 来源与读取质量、§0.1 触发原因
    raw/<site>-<n>.json       adapter 原始返回 · 永不编辑 · 每一行的来源终点
    journal.jsonl

  applications/<company>-<role>-<YYYY-MM-DD>/     ← 路径形状与旧 skill 逐字一致
    posting.yaml / posting-source.txt             posting-source 永不编辑
    evidence-blocks.json                          派生物 · 永不手改
    fit-assessment.{yaml,md}
    tailoring-plan.md
    claims.yaml                                   append-only · 撤回标 retracted，不删
    tailored-profile.yaml
    cv.{md,docx,pdf,tex} / letter.* / supporting-statement.md
    judge-round-<n>.json
    interview-brief.md
    mock/
      transcript-<n>.md        append-only · 每答一题即落盘
      assessment-<n>.md
      question-log.yaml
      open-loops.md
      cheatsheet.md
    journal.jsonl
```

**工作区路径形状是承重的**：旧 skill 的「续做未完成投递」功能就是按这个形状找的，一次自造布局的运行会**无声地**破坏续做能力。

**所有权**

| 模式 | 只读 | 独占写 |
|---|---|---|
| discover | profile, search-preferences | `searches/` |
| assess | profile, posting | `posting.*`, `fit-assessment.*`, `evidence-blocks.json` |
| apply | 上述全部 | `applications/` 其余全部 |
| interview | posting, tailored-profile, assessment, claims | `mock/`，外加向 `interview-brief.md` 追加 `## Walk-back list`、向 `claims.yaml` 追加 `source_kind: session-answer` 条目 |

**不可变清单及其理由**

1. `profile.yaml` —— 覆写是破坏性且不可恢复的，而且问题只在**下一次**投递时才浮现，那时「主档案」已经被上一个岗位窄化了。
2. 市场惯例表 —— 全套里唯一无源可引的断言类别。只有人工撰写、带日期、带来源种类的条目才有资格做这种断言。
3. 原始捕获（`raw/*.json`、`posting-source.txt`、`transcript-*.md`）—— 所有下游断言的来源链都终止于此。这些可编辑，来源追溯就是演戏。
4. `claims.yaml` 条目 —— 撤回的声明要留疤才有意义。
5. 只读保证 —— 不是偏好，是允许名单 + 事后 journal 扫描。

## 5. 四个模式

### 5.1 discover

**进入条件**（任一）：用户要找/比岗位；assess 判出 `大概率被筛掉` / `硬性阻断`；诚实缺口提前止损触发；assess 判出 `可以冲刺` 且用户未表明就要这个岗位；用户给了两个以上岗位（排序模式）。

> 这是 AI-Career-Committee 的「JD 适配闸门」重新锚定后的版本。**原闸门直接搬过来会永不触发**——它的五个触发条件里有三个引用了匹配分 `<65`、`<70` 和概率区间 `0-10%/10-25%`，而这两样东西已经被删掉了。改为锚定在投递建议档位上。
> 保留原文一条：**触发原因必须在搜索之前说明，并写进 shortlist。**

**步骤**

0. 说明触发原因，写入 `shortlist.md §0.1`；把本轮检索条件落成 `brief.yaml`（目标职位名、市场、城市、职级、雇佣类型、工作模式、语言、必须满足的约束、避开项、条数上限）。`brief.yaml` 是这轮搜索可复现的依据。
1. **登录态探测**：`opencli auth status -f json`。三种状态而非两种——`unknown` 返回的是**空字符串**而不是 `false`，必须重探。`indeed` 和 `51job` 根本不在列表里（无 auth adapter），这不是错误。
2. **来源选择**：优先无需登录的来源。`51job` 是唯一每个文档化字段都实测填满的 adapter。
3. **只读搜索**，单平台单轮条数封顶，**此阶段一律不取详情页**。
4. **行完整性检查**（先于任何其它处理）：断言标识字段 `title` 非空。`indeed` 实测 exit 0、JSON 合法、`title`/`salary`/`tags` 全空——必须逐行 `opencli indeed job <id>` 补回。
5. 归一化为 `JobListingEvidence`，跨平台去重。
6. **轻量分档**：先扫硬性资格阻断 → 命中直接判 `硬性阻断`；其余按序数规则分档。**词表与 assess 完全一致**（D3），但**每一条都必须盖上 `基于卡片信息的初判` 戳，且不带这个戳就不许渲染**。
   > 这个戳是承重的：discover 阶段手上只有卡片，assess 手上有完整 JD 和证据块。用同一套词表而不标注置信来源，等于用卡片数据冒充一次完整评估。**规则：discover 的档位永不被带进 assess——assess 一律重算。**
7. **只对前三档（`强烈建议投` / `值得投` / `可以冲刺`）取详情页**，`大概率被筛掉` 与 `硬性阻断` 不取。这是详情 fan-out 的上限所在，也是把翻页/取详情控制在黄层的具体机制。后两档在 shortlist 上只呈现卡片级信息，并注明「未取详情」——用户可以单独点名补取。
8. 保留原文一条：**若原 JD 已被判定不合适，本轮候选必须肉眼可见地比它更稳，而不只是标题相似。**
9. 写 `shortlist.yaml` / `shortlist.md` / 来源报告。

**失败处理**

| 情况 | 检测 | 动作 |
|---|---|---|
| 登录墙 | **exit 1、stdout 空、stderr 是 YAML（即使 `-f json`）** | 交叉核对 auth；把 `opencli <site> login` 交给用户自己跑（它是 write 命令）。不重试——登出状态下 403 是确定性的。**不要把 `strategy: public` 当作无需登录的证据。** |
| 静默部分抽取 | exit 0、JSON 合法、文档化字段为空 | 断言标识字段非空，走详情命令补齐，报告缺口。**绝不**从空字段推断「该站没有这类岗位」——行是存在的。 |
| 平台风控 | 每平台的触发串清单 | **立即停止。不重试、不改参数重试、不绕过。** 输出方向级降级 + 披露表。 |
| 零结果 vs 被挡 | **先看 exit code，再解释「空」** | 只有 exit==0 且 stdout 解析成数组，才叫「没有结果」。 |
| 桥接中断 | `opencli doctor` | 区分基础设施故障与单站问题。 |

**降级输出**：拿不到真实岗位时，输出**方向级 shortlist**（3–5 个目标方向、每方向检索词、建议筛选条件、为何比原 JD 更稳、要避开的标题与信号、手动收集优先序），外加一份**答案预填为「否」的披露块**：

```
本次会话已登录：        <是|否|不适用—无 auth adapter>
Adapter 返回：          <逐字错误信息>
收到限制信号后重试：    否
绕过任何平台控制：      否
取得真实岗位：          否
降级输出类型：          方向级 shortlist
```

第四项是关键：**一份答案预设为「否」的必需产物，使得隐瞒必须是一次主动覆写**，而不是一次省略。

**闸门 `check_shortlist.py`**
- 每行必须有 `source_site`、**在 `raw/` 里逐字出现的 `source_id`**、`retrieved_at`、非空 title、`why_matched`。
- 不得出现任何非 adapter 返回的 URL。无 URL 的来源必须给可追溯标识及其来源文件。
- 条数守恒；不足目标数必须有书面原因，**不许凑数**。
- **空结果消歧**：脚本读 `journal.jsonl`，除非至少一个 adapter exit 0，否则不许运行结果使用「没有匹配」这种措辞。（全部 adapter 阵亡与确实没找到，形状完全相同。）
- `check_no_write.py` 零命中。

### 5.2 assess

**进入条件**：存在一个岗位——URL、粘贴文本，或用户从 shortlist 里点名一行。

**步骤**

1. **抓取完整性闸门**。`200 OK` 不是拿到岗位的证据。阈值写在 SKILL.md 内联：约 300 词可读正文且有 requirements 段 = 可用；不足约 200 词、无资格类措辞、或出现登录/同意/机器人校验提示 = 阻断。阻断则请用户粘贴；彻底拿不到就停下说清楚。**绝不从登录墙上抽取 must-have**——那样产出的东西内部完全自洽而且全错。
2. **市场：直接问用户**（D14）。若 `search-preferences.yaml` 已存有目标市场，则**每次会话确认一次**即可，不必每个岗位都问；岗位所在地与已存市场不符时必须重问。之后由条目的 `applies_when` 在该市场**内部**做过滤。市场归不到 `cn/nl/de/uk/us` 任一时，诚实输出「本市场无惯例数据」并跳过惯例卡——**不拿邻近市场的惯例顶替**。
3. **抽取 `posting.yaml`**，完整字段表内联于 SKILL.md：`role_title, seniority, location, must_haves, nice_to_haves, responsibilities, keywords, company_values_tone, red_flags, salary_range, application_type`。
   > 旧 SKILL.md 的字段表**静默丢了 `salary_range` 和 `application_type`**，而 `application_type: structured` 是**唯一**导向 supporting-statement 分支的信号。这个压缩缺陷已经出厂了，不要重犯。
4. **硬性阻断项优先呈现**，并直接询问。
5. **切证据块**。`scripts/evidence_blocks.py`：`posting-source.txt` → `JD-nnn`，CV → `CV-nnn`。参数：单块上限 900 字符，每源上限 80 块，按空行或列表/编号/中文数字前的换行切分，超长段按 `[。.!?]` 再切句，丢弃不足 8 字符的块，id 三位补零。
6. **需求表**。每条 must-have 与每条具名职责一行：`level`(required/preferred/unclear)、`screening`(knockout/weighted/nice_to_have)、`match`(strong/partial/gap/no_evidence)、`recency`(current/recent/dated/undated)、`evidence: [{ref: CV-012}]`。
   > `level` 与 `screening` 拆开是这里最不显然的一处收益：大多数「必须」清单其实是许愿单，而**数标签**正是把一项缺失的资质从「停止」误判成「扣分」的原因。
7. **可数事实，无分数**：

   ```
   must-have 强证据：   X of N   （partial P，gap G，无证据 U）
   核心职责已证实：     M of K
   职级匹配：           <上跳 | 平级 | 下沉 | 不明>
   可补缺口所需投入：   <当天 | 一晚 | 数日 | 补不上>
   投递建议：           <强烈建议投 | 值得投 | 可以冲刺 | 大概率被筛掉 | 硬性阻断>
   ```

   N 和 K 里的**每一项都要连同其证据引用一起打印**，让分母可审计。`强证据`只数 `strong`；`partial` 与 `gap` 永不并进「已覆盖」的数里。只有陈旧证据的算 `partial`，不算 `strong`。
8. **拒答态**：输入撑不起结论时输出 `证据不足 — 不出结论`（读不到岗位、读不到 CV、图片源有不可辨区域、CV 只有技能清单没有支撑条目）。这是把 AI-Career-Committee 的「分数一致性闸门」从数字上翻译过来：**输入撑不起时，禁止给出自信的正面结论。** 旧 skill 没有这道地板。
9. **逐字渲染市场惯例卡**（按 id 白名单，只渲染 `applies_when` 命中的）。惯例**既不进投递建议，也不进任何一致性检查**。模型在这一节唯一自己写的句子是「这份简历在这条惯例上处于什么位置」，那句话和别的断言一样要引 CV 块。
10. **判为 `大概率被筛掉` 或 `硬性阻断` 时**，产出「那该怎么办」的另一半：从封闭集合里选**唯一**一个策略（投了再说 / 重新定位 / 技能冲刺 / 侧门切入 / 换方向），加一张 30/60/90 表（列：`目标 | 行动 | 验收标准`）和一份带 `输出物` 列的路线图。**`验收标准` 和 `输出物` 这两列就是全部价值所在**——它们把建议变成可检查的东西。

**闸门**：`check_assessment.py` + `check_evidence_refs.py` + `consistency.py` + `lint_no_prediction.py`
- 每个需求行至少一个可解析的证据引用，或 `match: no_evidence` 且无引用。
- 渲染文件里零个不可解析引用；读者可见的正文里零个块 id。
- 零百分比、零自造量表、零预测性词汇；免责声明存在；硬性阻断项渲染在结论之前。
- 一致性提示在触发处标注（**只报告，不修复**）。

### 5.3 apply

即被吸收的 `job-application` 全流程。此处只记**变化**。

**进入条件**：存在评估。`可以冲刺` 与 `大概率被筛掉` **不阻止**进入——为一个够一够的岗位做出一份扎实申请不是缺陷。`硬性阻断` 提示一次（「这是法律层面的门槛，不是表述问题，仍要投吗？」），用户说要就继续。

**五项变化**

1. **`claims.yaml` 成为必需产物。** 每个进入定制档案的 REFRAME / KEYWORD-INSERT / AMPLIFY 词条落一行：`{term, where, source_kind: profile-line|session-answer|fetched-artifact, source_ref, session_date}`。这把旧 skill 最高价值的**静默**规则（claim-provenance 检查点，目前不产出任何文件、任何引用列、任何 diff）变成 `check_claims.py` 能判死的东西。
2. **`scripts/parse_verdicts.py` 取代模型做解析。** 三个评委文件都写着「orchestrator 以程序方式解析此块」，而**这个程序不存在**。现在它存在：取每个评委最后一行 `VERDICT:`，只认严格的 `PASS`/`REJECT`，其余一律 `AMBIGUOUS`（fail-closed，重新派发）；AND 合并；抽出 `COVERAGE`/`SCORES`/`MISSING_OR_WEAK`/`LEVELING`/`STANDOUT_SIGNAL`/`SUPPLEMENTARY_QUESTIONS_FOR_CANDIDATE`；写 `judge-round-<n>.json`。顺带给了循环它目前缺的轮次计数器。
3. **渲染新鲜度做哈希。** `judge-round-<n>.json` 记录每个喂给评委的文件的 sha256；`check_render_freshness.py` 在哈希与磁盘不符时判该轮作废。拿旧渲染重判会产出一份**完全合法且自我印证**的判决——评委会把刚刚「已经修掉」的问题原样再报一遍。
4. **修复 Cluster-1 个人数据互锁并使其发声。** 实测漏出：`United States of America`、`US (Boston)`、`Los Angeles, CA`、`U.K.`、`remote (US)`；而 eval-0 的场景输入字面就是 `TARGET MARKET: United States (Los Angeles, CA)`。做法：匹配前先归一化（去括号内容、按 `,` `(` `/` 切分、逐 token 匹配）；市场归不到任何已知簇**且**存在个人数据时，向 stderr 发出点名字段的警告，绝不静默渲染。
5. **修复 `render_letter.py` 引擎缺陷。** `render_letter.py:101` 比较裸串 `"tectonic"`，而 `render_cv.py:992` 比较 `pathlib.Path(engine).name`；本机 `find_latex_engine()` 返回 `/opt/homebrew/bin/tectonic`，于是 CV PDF 生成（19,820 字节）而动机信 PDF 失败，**同一次运行、同一个引擎、51/51 测试全绿**（已复现）。修复方式：把 argv 构造提到一个共享 helper，并补上测试套件缺的那个回归测试——现有的 `test_letter_pdf_degrades_without_engine` 把引擎 monkeypatch 成 `None`，从来没走过 tectonic 分支，这正是坏渲染器能通过 51 项测试的原因。

**闸门 `check_apply.py`**：三个 PASS 均从 `judge-round-<n>.json` 解析得到，或记录了诚实止损原因并归类为**建得不好**还是**诚实够一够**；`tailored-profile.yaml` 里每个不在 `profile.yaml` 中的词条都能在 `claims.yaml` 找到；渲染哈希新鲜；`profile.yaml` mtime 未变；个人数据互锁已触发或已告警；`lint_cv.py` 与 `check_letter.py` 干净；`interview-brief.md` 存在。

### 5.4 interview

**进入条件**：工作区里有申请包，**或**用户给了岗位 + CV 并说自己有面试。

**架构（已定，理由是机械性的而非审美性的）**：**内联面试官 + 两遍 subagent 评估**，题库降级为种子材料。

> 派生的 subagent **没有和人来回对话的通道**：`agents/hiring-manager.md:21` 说输入在派发时一次性贴在 prompt 下方，`:97` 说必须以固定块结尾。没有提问后等待的通道。所以「subagent 当面试官」在任何权衡分析之前就被排除。而写死的题库无法追问——而「**在追问下站住**」是唯一比「说了」更有意义的档位。

**信息隔离——这是评估之所以诚实的机制**

| 角色 | 看得到 | **故意**看不到 |
|---|---|---|
| 面试官（内联） | `posting.yaml`、`cv.md`、`interview-brief.md`、市场×族的轮次形状、带日期的面经形状事实 | — |
| 评估第一遍 | `transcript-<n>.md`、`posting.yaml`、`cv.md` | **`interview-brief.md`、`claims.yaml`** —— 因此它无法把候选人**没说出口**的来源事实算作已答到 |
| 评估第二遍 | `transcript-<n>.md`、`claims.yaml`、`interview-brief.md` | 评分标准 —— 它唯一的工作是标 `UNSOURCED-FACT` / `OVER-CLAIM` / `CONTRADICTED` |

两遍**故意喂不同输入**，是把诚信绊线从一个意图变成一个机制的关键。

**步骤**：定轮次形状（市场 × 岗位族）→ 用生成题 + 面经题种下 `question-log.yaml`（每题带来源与日期）→ 内联跑一轮，面试官有具名人格 → **每答一题即刷盘 transcript** → 跑两遍评估 → 写 `assessment-<n>.md`、更新 `answer-bank.md` 与 `open-loops.md` → 进入第 n+1 轮时只带 open-loops 摘要，不带全文。

**面经使用规则（可直接粘进 SKILL.md）**

```
每条面经必须 (a) 用 detail 打开取未截断原文，(b) 在 question-log.yaml 里盖上它的 time，
(c) 展示给候选人时带上那个日期。
超过约 12 个月的，只能用来定形状（轮数、顺序、环节名），绝不当作具体技术题引用。
公司实体所在国与岗位所在国不一致时，除非帖子本身点名了那个国家，否则一律不用。
绝不把面经里的答案贴给候选人——只贴问题。
adapter 返回 403 或「需要登录」时，报告该来源不可用并改为生成。不要为绕过它去登录。
```

> 国别规则不是假想的：`nowcoder search "ASML 面试"` 返回了三条真帖，全部描述该公司**中国实体**的宣讲会/笔试流程，那不是 Veldhoven 的面试流程。公司名对、内容真、流程错，而且**看不出任何异常**——这是这个来源里最危险的失败。

**评分：档位，不是分数。** 四档按「证据出现程度」措辞，且**故意不编号，使其无法被平均**：`未出现` / `说了` / `举了实例` / `在追问下站住`，外加一个非档位标记 `与材料冲突`。**`在追问下站住` 就是天花板**，这是刻意的——英国公务员公开量表里有「超出该级别期望」这样的档，而本模块并不知道那个级别的期望是什么。

**唯一一处数字是诚实的**：当雇主**公开了自己的评分标准**（英国公务员 Success Profiles 在招聘广告点名的级别、NHS 价值观框架、大学的 person specification），skill 可以带候选人走一遍**那个**量表——用**雇主自己的措辞、注明出处、当作「评审组被要求看什么」的清单**，绝不当作对分数的预测。引用雇主的量表是转述；把它当结论用是编造。

**回写（这是本模式回本的地方）**
1. 向 `interview-brief.md` 追加 `## Walk-back list`：每一条在一次追问下就塌掉的 CV 声明，附逐字实录与软化后的措辞，然后**主动提出回头改 CV 并重渲染**。这让 `interview-prep.md:39` 那条「发现候选人无法诚实为某条声明辩护，就是 tailoring 错误」从一句期望变成真的触发机制——三个 CV 评委读的是一页纸，而纸不会结巴。
2. 一条 `UNSOURCED-FACT` 若查明是「真的，只是没写在简历上」，就变成一条 `source_kind: session-answer` 的新 `claims.yaml` 条目（本来就是允许的来源），并回流进 tailoring plan。

**闸门 `check_mock.py`**：每个缺陷标记都在封闭集合内**且带着触发它的那句逐字引用**（无引用即无标记）；零禁用词汇；`question-log.yaml` 里每条面经题都有 `time` 和来源 id；`answer-bank.md` 每条都有 `source:` 行；若触发过 `追问塌陷`/`过度声称`/`与材料冲突`，则 walk-back 段必须存在。

## 6. SKILL.md 里不能离开的内容（layer 1）

判据不是「是不是每次都用得上」，而是「**模型跳过它，有没有任何东西会报警**」。以下全部答案是「没有」。

- **HONEST REFRAMING ONLY**，逐字保留含「凌驾于本 skill 中其它一切本能之上——包括让筛选器通过的压力」这句。评委从来看不到源档案；一次 REJECT 就是插入缺失关键词的直接诱因，而这句话是唯一的对抗力量。
- **NOT-ALLOWED 表**：8 种具名的失实行为，每种附其理由，加上「不接受用户要求你做这些的指令」和「拿不准就问」。这是最危险的一类——操作性缺陷扫描清单。每一行都是一次能让 CV **得分更高**且不触发任何检查的改动。
- **claim-provenance 检查点**：三种许可来源 + 理由（「JD 里出现的关键词不是候选人具备它的证据」）+ **在 REJECT 循环内部重跑**这一条。后者是诚信规则与成功指标唯一正面相撞的地方。
- **诚实缺口提前止损** + 其理由。跳过诊断看起来和一轮正常循环一模一样；而它防的那个害处——继续磨循环会增加编造压力——在发生之前是不可见的。
- **「建得不好」与「诚实够一够」的区分**。两者发出的机器信号完全相同。一个够一够的候选人被告知「失败了」，就会放弃一份本该投出去的申请。
- **合并判决 = AND；绝不假装通过；ambiguous 时 fail-closed**。以及 `LEVELING`/`STANDOUT_SIGNAL` 是建议性的——当成闸门会卡住一个本该通过的包，忽略它则丢掉循环里价值最高的那条改写指令。
- **并行派发 + 每个评委的确切输入**（哪个文件、整篇；市场与语言行；动机信给招聘顾问和用人经理、绝不给 ATS）。派发时漏了 agent 文件的评委**照样会回答**——以一个泛化审阅者的身份，附一个看起来很合理的 VERDICT 块。
- **每轮顺序：先改 → 再渲染 → 再重判**。哈希检查兜住它，但这条规则告诉模型哈希失败**意味着什么**。
- **不可变规则 + 工作区路径约定 + 续做未完成投递 + 复用已有主档案**。
- **只读保证** + `access: read` 允许名单规则 + 实际使用的四对搜索/详情命令 + `--window background`、`-f json`、**先看 exit code 再看 stdout**、indeed 空 title 缺陷。
- **平台限制停止规则**（停、不重试、不改参数、不绕过、输出方向级降级、填披露表）。每平台的触发串是数据；这条教条不是。
- **投递建议块模板 + 必需免责声明**。免责声明是阻止一个计数被读成一个预测的东西。
- **禁用输出词表** + 雇主公开量表的例外（引用、注明出处、绝不断言分数）。
- **反教唆四条规则 + 绊线**。跳过它什么都不会响，会话只是安静地把候选人教成撒谎。
- **等价测试（诚实 ≠ 畏缩）**。这是诚信规则的配重，且**完全没有闸门**——低报对每个评委和每个测试都是不可见的，而它恰恰系统性地低估了这个 skill 最该服务的那批人：够一够的候选人和转行者。
- **硬性阻断是一堵墙**（今天 `grep disqualifier SKILL.md` 返回空）。一个假的「缓解说明」在招聘顾问评委看来算作**已处理**。
- **量化回退阶梯（5 级）+ 非量化职业的定性证据规则 + 陈旧度降级**。没有阶梯，模型只有两个可执行选项：含糊，或编造。而那个「软指标」是一个能让 CV 在粗读下**变好看**的编造。
- **LEAD-WITH 优先级 + 点名被砍掉的内容**。没有渲染器测量页面位置；一份覆盖良好但顺序糟糕的 CV 会直接通过 ATS 闸门。
- **AI 均质化检查的四个具名维度**。它的害处**完全落在真实的人类招聘者身上**，在这个 skill 能观察的所有循环之外。
- **Cluster-1 个人数据互锁**。法律后果最重，且其文档声称的 backstop 对可信输入是假的。
- **岗位抓取完整性阈值 + 平台清单**。整条流水线「垃圾进」的根。
- **完整抽取字段表**，含 `salary_range` 与 `application_type`。
- **结构化申请的评审替换规则**（它静默覆盖了一条 SKILL.md 自称「不可协商」的规则）。
- **本地化称谓表**（DE/FR/ES/IT/NL，具名收件人规则，绝不用 `To Whom It May Concern`，绝不猜名字）。渲染完美、无闸门可读、在真实雇主处一眼被发现。六行。
- **模拟面试会话机制**：信息隔离、每次派发一轮、每答一题刷盘。
- **接地契约摘要**（§7 的三机制图）。
- **闸门表**：每个闸门、其脚本、以及「模式不得在 `journal.jsonl` 里没有回执的情况下宣称成功」。
- **自检清单，点名每一个 reference 文件、每一个脚本、每一个模式文件**。
  > 这是最重要的一处结构性发现：现有 skill 里 `grep -n "checklist\|self-check" SKILL.md` 只命中一行，而那行是关于 JD requirements 的散文。**用户自己文档里写的第三种 backstop 形式，在现有 skill 里根本不存在。**

**明确承认没有 backstop、只能靠内联的**（诚实清单）：HONEST REFRAMING 的仲裁条款；等价测试；建得不好/诚实够一够之分；反教唆四条；`LEVELING`/`STANDOUT_SIGNAL` 的建议性；评委分工边界与 `>=3` 招聘顾问 / `>=4` 用人经理的**刻意不对称**（这是**集合**的性质，所以没有任何单个 agent 文件能强制它，也没有任何代码在组合它——打破这个不对称，「诚实够一够」就变得无法陈述）；快速路径的有限授权；从候选人自己的论文与仓库富化（含「诚实归因」那一半，这是第三种来源唯一合法放宽的地方，读错会产出一个**背后有真实引用**的编造）。

## 7. 确定性检查

按「这个缺陷是否已经咬过人」排序。

### P0 — 关闭已实测的活体缺陷

### P1 — 关闭输入已展示的缺陷类别

`consistency.py`（移植自 marketfit `consistency.js`：结论与投入冲突、knockout 行过多、可补缺口多于行动条数；外加工作许可对齐：`要求已有许可 × 需要担保 → 冲突`，`× 学生/毕业生` 或 `× 临时通道 → 需核实`，**绝不判为冲突**——把它叫冲突会错杀本可行的申请。**只报告、不修复**：代码能看出两个字段不一致，看不出哪个是对的）；`lint_cv.py`；`check_letter.py`（`body` 字符串里的 markdown 标记会**逐字渲染**——`**bold**` 会打印四个星号）；`check_mock.py`；`render_cv.py` 的 heading/order 警告（实测：一个法务 CV 因为 key 拼错而**静默**丢掉「Selected Matters」标题）；`check_skill_lossless.py`。

### P2

`check_pages.py`；`render_rirekisho.py` 日期哨兵（`_ym('Sep 2023')` 现在返回 `('','')`，产出年/月空白的、结构上无效但能渲染能保存能通过 pytest 的表格）；`check_word_limits.py`；`count_coverage.py`（**唯一**的产数路径，因此不存在第二个能与之打架的数）。

**测试纪律**：每个检查的测试必须把「不该响」的情况钉得和「该响」的情况一样死——一个对正常输出乱叫的检查比没有检查更糟，因为读者会学会跳过那一行。以及：只 import 模块的测试只能证明按钮存在，证明不了按下去有反应——这正是 51/51 全绿掩盖了一个坏渲染器的原因。

## 8. 接地架构

三个机制，三种不同职责，互不替代。

```
  原始来源文本                    skill 说了什么              谁在检查
  ─────────────                  ──────────────             ────────
  posting-source.txt  ──切块──► JD-001…JD-080  ──被引用──► 需求表行
  cv.md / profile     ──切块──► CV-001…CV-080                  │
                                                                ▼
                                                    check_evidence_refs.py
                                                    （解析得到，或丢弃）

  profile.yaml 某行  ─┐
  本次会话的回答     ─┼────► claims.yaml ──被要求──► 每个 REFRAME /
  已读取的本人产物   ─┘                              KEYWORD-INSERT 词条
                                                                │
                                                                ▼
                                                         check_claims.py

  一个人，在一次提交里 ────► market-conventions/<key>.yaml
                                    │  id 白名单 · 逐字渲染
                                    │  绝不经模型转述
                                    ▼
                             check_conventions.py
```

1. **证据块把「分析」绑在源文本上。** 模型只能引用存在的块；每个引用在到达时解析，解析不了的**丢弃而非致命**。空证据列表不是错误——拒绝它会把诚实的形状惩罚掉，而一个**编造的**引用同样落进那个空数组、照样放行。诚实的边界要带进 skill 自己的输出：**这是一个可信性下界，不是证明——它保证一个断言指向真实存在的东西，不保证该断言由它推出。**
2. **claim-provenance 把「输出」绑在源事实上。** 三种许可来源，没有第四种。`claims.yaml` 第一次让它变成一个可 diff 的产物。
3. **市场表绑住唯一一类无源可引的断言。** 整个 skill 里，只有一类陈述无法追溯到用户提供的文本：这个市场在筛什么而岗位启事没写。所以它由人撰写、带日期、带来源种类、按 id 白名单、**逐字渲染**——模型不能把「通常」加强成「必须」，不能给它加个数字，不能凭空造一条。

**两个值得单独点名的模式**

- **在诱发违规的那个字段旁边，把栅栏再说一遍。** 一条写在五十条指令顶部的规则，不是模型写那个危险字段时所站的位置。禁编造规则要在**恰好三处**重述：KEYWORD-INSERT 步骤、模拟面试的出题（一个 CV 不支持的问题前提，是一个**由候选人随后复述**的编造）、以及 shortlist 的 `why_matched` 字段。
- **模型可靠地不服从的指令要删掉，规则移进代码。** marketfit 删掉了「不要用 Markdown 代码围栏」这条指令，因为模型三次运行三次都以 ```` ```json ```` 开头——那条指令什么也没买到，而且「**一条被可靠违反的指令，也教坏了它周围的那些**」。第一批真实运行之后要专门审计这个。

## 11. 风险登记册 —— 会静默失败的地方

每一行都是「通过了自己所有检查，却交付了错误东西」的一种方式。

| # | 静默失败 | 为什么没有东西会报警 | 对策 |
|---|---|---|---|
| 1 | 平台什么也没返回，模型把空缺**填上**了看似合理的岗位 | 编造的 shortlist 内部自洽、格式完美、每个字段形状都对 | 每行 `source_id` 必须在 `raw/` 里逐字出现，脚本去 grep；不足数必须有书面原因；降级输出是**具名产物** + **答案预填为「否」的披露表**，使隐瞒必须是主动覆写 |
| 2 | 所有 adapter 都死了，运行结果说「没有匹配的岗位」 | 「没找到」与「全都失败」形状完全相同 | `check_shortlist.py` 读 journal，除非至少一个 adapter exit 0，否则不许用「没有结果」措辞 |
| 3 | exit 0 但字段全空，被当成「没有数据」 | 所有状态检查都通过，JSON 也合法 | 断言返回行的标识字段非空（而不是只看 exit code），走详情命令补齐。**绝不**从空字段推断不存在——行是存在的 |
| 4 | 市场惯例过期了 | 一张错的市场卡没有任何读者能核对的引用，读起来和对的一模一样 | 每条带 `retrieved` + `review_by` 且都被 lint；卡片上显示取回日期；禁数字规则使**数值型**过期在结构上不可能（条目写「到 <官方页面> 查当前数额」而不是带一个数）。**具名残余风险**：一条惯例可能是**实质性错误**而非数值过期，没有任何东西能检测——只有人工复核能 |
| 5 | 中文版说的比英文版更强 | 两版都会渲染，没有读者同时看两版 | 复核已多次发现此问题（源文说「引导」中文写成「被要求」，法条只是限定权利范围中文写成「根本不含」）。部分对策：`check_conventions.py` 要求两个字段都在，对长度比失衡和情态动词不对称（`must`/`必须` 只在一版出现）告警。**具名残余风险**：语义漂移不可脚本化，复核是人的活 |
| 6 | 一条 `unverified` 备注声明免责，而渲染出的正文照样在做那个断言 | `unverified` 字段跟表一起出厂，但那不是用户读的东西 | `unverified` 条目必须点名它免责的字段；`check_conventions.py` 对 unverified 备注与 `text_en`/`text_zh` 的关键词重叠告警。内联规则：**unverified 段免责的每一个断言，都必须从渲染文本里删除，而不是加个脚注** |
| 7 | 模拟面试教唆了一次失实陈述 | 候选人同意了，回答库看起来是审核过的，编造在真实面试现场才浮现 | 绝不替候选人写答案——点出缺口，不填它。不用引导性问题，不用 CV 不支持的问题前提。**第一遍评估看不到 `claims.yaml`**，所以它无法把没说出口的事实算作已答到。`check_mock.py` 对没有 `source:` 行的回答库条目判死。无法辩护的声明进 walk-back 清单，不进排练 |
| 8 | 评估因为是数字而读起来很精确 | 「11 项里的 8 项」带着算术的权威感 | 11 项里**每一项**都连同证据引用一起打印，分母可审计，读者可以对某一行提出异议。`lint_no_prediction.py` 禁百分比与自造量表。结论是一个词。免责声明就在计数下方。`count_coverage.py` 是唯一产数路径，不存在第二个数与它打架 |
| 9 | 评委在陈旧渲染上重跑 | 判决块完全合法，而且**自我印证**——评委会把刚刚「已经修掉」的问题原样再报一遍 | 派发时哈希每个文件进 `judge-round-<n>.json`；不符则该轮作废 |
| 10 | Cluster-1 互锁没有触发 | CV 渲染完美，每个评委都被告知按拿到的市场校准 | 归一化匹配 + 未知市场带个人数据时大声告警 + 对真实拼法的 fixture 测试。失败输入不是假想的：eval 场景字面写着 `United States (Los Angeles, CA)` |
| 11 | 某个 reference 文件从来没被读过 | 构建成功、lint 通过、输出安静地错着 | **本 skill 内部已有实测先例**：一次运行记录下「`references/motivation-letter.md` 未被显式读取」，然后提交了一条「本 skill 缺少某项指引」的发现——而那项指引就在它选择不读的那个文件里。对策：layer-1 自检清单点名每个文件；闸门脚本要求只有该文件定义的产物字段；最高后果的内容移到内联。**诚实的具名残余风险**：`candidate-situations.md` 的八套打法与簇惯例内容只有部分 backstop |
| 12 | 一个闸门「通过」了，其实它根本没跑 | 被跳过的脚本不产生输出，而那看起来和一个干净的脚本一样 | 闸门写回执（`{gate, input_hashes, verdict, ts}`）进 `journal.jsonl`；模式的完成消息必须引用回执；下游闸门要求上游回执 |
| 13 | 跑了一条写命令 | 发出去的招呼不可撤回，且本地不留痕迹 | 允许名单取自工具自己的 `access:` 元数据 + 事后 journal 扫描。不留「确认后发送」的逃生口 |
| 14 | 一条面经描述了**对的公司、错的国家**的流程 | 公司名匹配，内容是真的 | 国别规则 + 日期戳 + 超过 12 个月只用形状。已在 ASML 与 Philips 上实测验证。另需过滤广告：探测中有两条帖子是伪装成面经的商业推广 |
| 15 | 一个检查乱叫，然后被无视 | 一个大家学会跳过的闸门，会在真正要紧的那次运行上失效 | 每个检查的测试都把「不该响」钉得和「该响」一样死；每个无法判定的检查**只报告不修复**——代码能看出两个字段不一致，看不出哪个对，而静默择一等于把一个可见的矛盾换成一个不可见的猜测 |

## 12. 迁移纪律

- `scripts/check_skill_lossless.py` 进 CI：断言旧 `job-application` 树的每一行实质内容都能在新树中找到，删除项进允许名单且每条附书面理由。
- **这个检查证明不了的事**：它衡量的是字节是否还在，不是内容是否在**需要的时刻**到达上下文。唯一真正的检验是**跑完整的 end-to-end eval，然后看输出缺了什么**。
- **一处已标记的改写**：FIT SNAPSHOT 的免责声明按纪律应逐字搬运，但那段免责声明讲的是**关键词覆盖百分比**，而新 skill 不再输出这个。逐字搬过去会出厂一段自相矛盾的文字。因此这是一次真正的改写：**单独一个小的、可读的提交**，不夹带进迁移 diff，并在允许名单里具名记录。
