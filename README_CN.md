> **一个会读你真实经历、拒绝替你美化、把猎头只在私下说的话直接讲给你听，
> 并且在交付前先让三个互不相干的筛选者过一遍的求职教练。**

以 skill 的形式跑在 Claude Code 或 Codex 里。你跟它对话，读材料、改简历、排版、评审都归它，
最后 `.md` 和 `.pdf` 直接落到你的下载文件夹。

大部分简历工具优化的是「贴上岗位链接后的那六十秒」。这个工具优化的是四周后的面试：
纸上每一行，你都得能当场兜住。

## 它不会做的四件事

下面每一条都由会让整轮失败的脚本兜底，不是靠一段「请你不要这样」的提示词。

**不编造。** 没用过的技能不写，职级不抬高，日期不动，你说不出具体数字时不会出现
「性能提升 40%」。进简历的每一条主张都必须能追到：你原始档案里的某一行、你这次对话里
亲口给的回答，或者它真的读过的你本人的论文 / 仓库。追不到的一律进「诚实差距」清单，摆给你看。
它防的是一个非常具体也非常常见的翻车：模型在 JD 里看到 Kubernetes，就把它写进你的简历，
然后你在技术面上当场露馅。

**不预测你的概率。** 没有「匹配度 82%」，没有面试概率，没有 0–100 分。
这类数字是编的，看上去却很权威，而人是真的会照着它做决定。它给你的是必备项的逐条清单，
每一条后面直接印着证据出处，于是你可以只反驳其中一行，而不是去反驳一个数。
这条规则由一个中英双语的 lint 强制执行。

**不自己给自己打分。** 申请包会被送给三个上下文全新、互不相干的评审：ATS 解析器、
按真实节奏只花十五秒扫一眼的 HR、按可信度细读的用人经理，三个都通过才算过。
如果没过、而且差距是真的，流程会停下来，直接告诉你这份简历在不撒谎的前提下补不上。
这就是正确答案。那种直接把关键词塞进去糊弄过去的工具，只是把你的拒信推到了更靠后、
成本更高的那一轮。

**不替你猜地区。** 每一轮需要地区的环节都会先问你，并给出具体选项，绝不拿你过去
在哪儿工作过来推断。简历记录的是你的经历，它并不说明你想投哪里。

## 四个模式，彼此不自动串联

| 模式 | 回答的问题 | 你拿到什么 |
|---|---|---|
| **discover 找岗** | 市面上有什么值得看 | 每一行都能追回真实岗位的候选清单，各带一个初判 |
| **assess 判断** | 这个岗位值不值得投 | 逐行对照的匹配评估，硬性门槛排在最前，外加一个诚实结论 |
| **apply 申请** | 怎么做出一份能过筛的申请包 | 定制简历、可选求职信、三判官评审、`.md` + `.pdf` |
| **interview 面试** | 该怎么答，以及我刚才错在哪 | 一轮模拟面试，然后复盘哪些主张你没兜住 |

找到三十个岗位不会自动生成三十份简历。每个模式结束时会告诉你下一步可以做什么，然后等你选。

## 中国市场：同一个岗位名，四种完全不同的工作

同样叫「算法工程师」，在大型私企、中小型私企、国企、外企，工作内容、工时、
薪资结构和稳定性完全不是一回事。所以 `cn` 这一轮会多问一个多选：你倾向哪几类雇主。
51job 每张卡片本身就带 `companyType` 和 `companySize`，所以这个偏好能落到真实数据上，
不用靠猜。

这是**排序偏好，不是过滤器**：不在你选择范围内的岗位不会被悄悄删掉，而是排在后面，
并在 `why_matched` 里注明它属于哪一类。你要的是有侧重，不是一堵墙。

平台这块它说的是实话，不摆花架子：中国区不需要登录就能搜的是 51job，
BOSS 直聘需要你先在浏览器里登录，它会说清楚再等你。牛客和一亩三分地都有搜索命令，
但它们返回的是面经和论坛帖，**校招轮次值得去读，但不产出候选清单的行**，
因为一条论坛帖不是一个能追溯 `source_id` 的岗位。

中国市场的惯例卡有 10 条，都带出处链接和复核日期，包括几条容易踩的：
BOSS 上真正被筛的是在线资料而不是简历附件；三方协议不等于劳动合同；
应届生身份是行政认定、有明确的判断口径；招聘启事上的薪资本身就不是一个有定义的量。

## 个人信息是个陷阱，而且方向反了会更糟

<p align="center">
  <img src="docs/assets/personal-data.jpg" alt="一份没有照片和出生日期的美国简历，旁边是保留了两者的德国简历">
</p>

美国简历上放照片和出生日期，会给对方招来歧视诉讼的风险，受过合规训练的 HR 会直接把它丢掉；
同样的照片和出生日期放在德国简历上却是常规操作，不放反而显得不上心。
这两个错误的代价不对称，所以规则也不对称：美国、加拿大、英国、爱尔兰、澳大利亚、新西兰
一律抹掉这些字段，并且**明说抹掉了**；遇到没有惯例表的市场，则一律保守不渲染，并告诉你原因。

内置五张惯例表，覆盖美国、英国、德国、荷兰、中国，共 38 条，每条都带来源链接、抓取日期和复核日期。
过了复核日期，条目照常渲染，但会顶着一条「已过期」的横幅。
一张卡悄无声息地过期，比一张承认自己过期的卡危险得多。

## 它能产出什么

**简历**：Markdown、`.docx`、PDF（走 LaTeX 排版，推荐 `tectonic`）。
**求职信**：同样三种格式。**日本履历书**：有自己的表单渲染器。
**英国 NHS 和公务员体系**的能力框架表单走专门的分支：按每条评分标准分开写、
卡住雇主给的字数上限，因为那才是这类雇主真正打分的材料。

非英语输出是一等公民，不是事后翻译：荷兰语、德语、法语、西班牙语、意大利语、
中文、日语、韩语的简历都会按对应语言渲染个人信息栏和小节标题，
而那些抓 AI 腔、抓学位后面掉了「（在读）」的检查，在这些语言里同样生效。

成品直接落在 `~/Downloads`，命名是 `<公司>-<岗位>-<日期>-cv.md` 和 `.pdf`，不用再去翻文件夹。

## 到底测了什么

两个数字，回答的是两个不同的问题。

**`make check`：3321 个测试全绿。** 它只说明代码的行为和它自己的测试一致，仅此而已。
闸门通过不等于产物正确。这个仓库自己被「全绿但产物是错的」坑过太多次，所以把这句话写在明处。

**`evals/`：20 个场景，两条臂。** 有意义的是两臂对比，因为**两条臂都有的行为，
是模型的能力，不是这个 skill 的贡献**。第 2 轮（2026-09-05/06）跑了 15 次带 skill 的运行，
每一次都和同场景的基线运行一一配对。**十条能区分两臂的判据，基线全 FAIL，带 skill 全 PASS**：
个人信息的抹除是「说出来的」而不是悄悄的；被平台挡住的找岗轮次会带着披露块交付，
而不是安静地少给几行；输入太薄时拒绝出结论的下限守得住；
申请环节遇到真实差距会诚实停下；面试模式不吐 hire 结论、也不编分数。

**每格 n = 1。** 这只说明每条行为在一次运行里达到了，不说明它多久达到一次，也不构成置信区间。
场景表和断言表都是写这个 skill 的人自己写的，所以每条断言都必须附一个 falsifier，也就是
「不合格的输出长什么样」，在跑之前就写死。完整记录（由 grading 文件生成，不是手打）在
[`evals/iterations/iteration-2-with-skill.md`](evals/iterations/iteration-2-with-skill.md)。

## 安装

三条路，任选一条。都需要 **Python 3.10+** 和两个包，剩下的交给最后那句 `doctor.py`。

**一行搞定，用 [`npx skills`](https://github.com/vercel-labs/skills)** —— 最省事：

```bash
npx skills add addsumtech/job-hunt
```

它会问你装到哪个 agent、什么范围。`-g` 是全局装，`-a claude-code` 或 `-a codex`
可以跳过 agent 那一问，`-y` 全程不交互。这个仓库的根目录**就是** skill 本身，
所以整个目录会被拷进你的 skills 文件夹。

**作为 Claude Code 插件** —— 有托管更新，也是唯一能覆盖云端会话的路径：

```text
/plugin marketplace add addsumtech/job-hunt
/plugin install job-hunt@job-hunt
/reload-plugins
```

插件里的 skill 带命名空间，所以调用时是 `/job-hunt:job-hunt`。两件事值得知道：
如果你**同时**在 `~/.claude/skills/` 里留了一份手动拷贝，会看到这个 skill 出现两次，
没有任何去重机制；另外第三方 marketplace 不会自动更新，要拿新版本得跑
`/plugin marketplace update job-hunt`。

**clone + 软链** —— 如果你打算改它，选这条：改完立刻生效，插件缓存做不到这点：

```bash
git clone https://github.com/addsumtech/job-hunt.git
ln -s "$(pwd)/job-hunt" ~/.claude/skills/job-hunt     # 或 ~/.codex/skills/job-hunt
```

不管走哪条路，装完都跑一次：

```bash
pip install -r requirements.txt              # PyYAML, python-docx
python3 scripts/doctor.py --install          # 体检这台机器，pip 能装的自动装
```

`doctor.py` 检查的是**能力**而不是二进制文件名：它直接渲染一份 PDF，而不是去找 `xelatex`。
早先的版本就是去找二进制名，没找到，于是报告「PDF 渲染有风险」，而机器上装的是 `tectonic`，
每份 PDF 其实都好好的。它只装 Python 包，从不动系统级二进制；
需要 LaTeX 引擎时，它把你这个平台该跑的那一条命令打出来，交给你自己执行。

## 然后直接说你要什么

```text
用 job-hunt 帮我找上海的算法工程师岗位，我想看国企和外企。
用 job-hunt。这是岗位链接和我的简历，值得投吗？
用 job-hunt 把我的简历改到这个岗位上，顺便写求职信。
用 job-hunt 给我刚投的那个岗位做一轮模拟面试。
```

它会先问一小轮带选项的问题：先定地区，再告诉你这个地区实际有哪些平台可用，
其中哪些需要你先去浏览器登录。答完就开始。

## 在 Codex 和其它 agent 上

执行层的那一半（所有闸门、日志、渲染器、覆盖计数）是只依赖两个包的纯 Python，
所以在任何能跑 Python 3 的地方行为完全一致。各家 agent 之间不同的只有两件事：
怎么向用户提问，以及怎么给评审开一个全新上下文。
[`references/portability.md`](references/portability.md) 给出了这两件事的替代写法。
三个评审人格已于 2026-09-06 通过 `codex exec` 端到端实跑过一个真实的申请工作区，
skill 自己的判定解析器接受了全部三份并记录为 PASS。
同一台机器上还有 `gemini` 和 `cursor-agent`，**没有测过**，这里也不声称它们能用。
