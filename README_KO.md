**채용 공고를 찾고, 지원할지 판단하고, 서류를 다듬고, 면접을 연습합니다. 해 온 일을 분명하게 전달하면서 아직 충족하지 못한 조건도 확인합니다.**

job-hunt는 Claude Code와 Codex에서 사용하는 취업 지원 Skill입니다. 목표, 이력서 또는 채용 공고를 제공하면 에이전트가 자료를 읽고, 근거를 확인하고, 문장을 다듬고, 문서를 조판하고 검토합니다. Python 스크립트는 출처, 파일 간 일관성, 결과물 전달 조건을 검사합니다. 기술·연구 직군을 비롯한 여러 분야와 직무 전환, 경력 공백, 신입 지원, 해외 취업 등의 상황을 다룹니다.

목표는 이력서의 어느 문장을 질문받아도 실제 경험으로 설명할 수 있게 하는 것입니다.

## 지금 필요한 단계부터 시작하세요

| 모드 | 사용하는 상황 | 주요 결과물 |
|---|---|---|
| **discover · 공고 탐색** | 방향은 정했지만 검토할 공고를 찾고 싶을 때 | 실제 공고 출처, 수집 상태, 잠정 평가가 포함된 후보 목록 |
| **assess · 지원 검토** | 관심 있는 공고에 시간을 투자할지 판단할 때 | 요건별 근거 비교, 필수 자격 조건, 부족한 점, 지원 조언 |
| **apply · 서류 준비** | 지원할 직무를 정하고 맞춤 서류가 필요할 때 | 맞춤 이력서, 선택적 지원 동기서, 검토 기록, 면접 준비 자료 |
| **interview · 모의 면접** | 공고와 이력서를 바탕으로 답변을 연습하고 돌아볼 때 | 모의 면접 한 회차, 대화 기록, 독립된 두 평가, 추가 확인 사항 |

각 모드는 따로 사용할 수 있습니다. 한 회차가 끝나면 다음 선택지를 제시하고, 계속할지는 사용자가 결정합니다. 공고 목록을 만들었다고 이력서를 일괄 생성하지 않습니다. 완성된 서류의 제출 여부와 실제 제출도 사용자가 담당합니다.

설치 후에는 다음과 같이 요청할 수 있습니다.

```text
job-hunt를 사용해서 네덜란드의 MRI 영상 재구성 관련 채용 공고를 찾아 주세요.
job-hunt를 사용해서 이 공고 링크와 제 이력서를 보고 지원할 만한지 평가해 주세요.
job-hunt를 사용해서 이 직무에 맞게 이력서를 다듬고 지원 동기서를 작성해 주세요.
job-hunt를 사용해서 이 공고와 제 이력서를 바탕으로 기술 모의 면접을 진행해 주세요.
```

에이전트는 먼저 모드와 지원 지역을 확인한 다음, 필요한 선호 조건과 자료를 묻습니다. 지역은 사용자가 확인하며, 이전 근무지나 대화 언어만으로 추정하지 않습니다.

## 실제 경험을 지원서에 반영하는 방식

**모든 주요 서술에 근거를 연결합니다.** 새로 추가하는 기술, 도구, 담당 범위, 성과는 원본 프로필의 구체적인 내용, 해당 세션에서 사용자가 한 답변, 또는 실제로 읽은 본인의 논문이나 프로젝트로 뒷받침되어야 합니다. 기존 경험은 순서를 바꾸거나 강조하거나 다시 표현할 수 있습니다. 근거가 없는 내용은 부족한 점 목록에 남깁니다. `claims.yaml`에 대응 관계를 기록하고, 맞춤 작업에는 프로필 사본을 사용해 원본을 보존합니다.

**평가 근거를 요건별로 보여 줍니다.** 필수 요건은 충분한 근거, 부분적 근거, 근거 없음으로 나누고, 취업 허가나 면허 같은 필수 자격 조건을 먼저 확인합니다. 자료가 부족하면 `insufficient_evidence`를 반환하고 필요한 자료를 설명합니다. 면접·채용 확률이나 임의의 0–100 적합도 점수는 만들지 않도록 규정하며, 예측 표현 검사는 이력서가 지원하는 아홉 언어의 사전 정의된 문구를 확인합니다. ATS 키워드 포함률은 문서의 표현을 측정하는 값이며 채용 가능성이 아닙니다.

**일반 이력서는 세 개의 독립된 AI 검토를 거칩니다.** ATS 검토자는 키워드와 파싱 가능성을, 채용 담당자 검토자는 가독성과 기본 지원 자격을, 현업 책임자 검토자는 경험, 담당 범위, 신뢰성을 확인합니다. 각각 별도의 컨텍스트에서 실행하며 모두 `PASS`일 때 내부 검토를 통과합니다. 수정할 수 있는 문제는 고친 뒤 다시 검토하며 최대 세 회차까지 진행합니다. 사실에 충실한 수정으로 해결할 수 없는 격차만 남으면 이유를 설명하고 일찍 종료합니다.

**면접 피드백은 실제로 말한 내용을 확인합니다.** 한 평가는 답변 자체를, 다른 평가는 사실의 출처를 검토합니다. 이미 가진 경험을 정리하고 불분명한 내용을 확인하도록 도우며, 뒷받침할 수 없는 이력서 문장은 수정 목록에 넣습니다.

## 설치

로컬 명령을 실행하고 파일을 읽고 쓸 수 있는 에이전트 환경과 **Python 3.10+**가 필요합니다. `npx` 설치에는 Node.js/npm도 필요합니다. 아래 세 가지 중 하나를 선택하세요.

### 방법 1: `npx skills`로 설치

```bash
npx skills add addsumtech/job-hunt
```

안내에 따라 에이전트와 설치 범위를 선택합니다. 사용자 전체 범위로 설치하려면 `-g`, 에이전트를 지정하려면 `-a claude-code` 또는 `-a codex`, 확인 프롬프트를 건너뛰려면 `-y`를 사용합니다. 저장소 루트가 Skill 본체이므로 스크립트와 참고 파일도 함께 설치해야 합니다.

### 방법 2: Claude Code 플러그인으로 설치

Claude Code 안에서 실행합니다.

```text
/plugin marketplace add addsumtech/job-hunt
/plugin install job-hunt@job-hunt
/reload-plugins
```

`/job-hunt:job-hunt`로 호출합니다. 마켓플레이스 갱신에는 `/plugin marketplace update job-hunt`를 사용합니다. 수동 복사본과 플러그인을 함께 설치하면 같은 Skill이 두 번 표시될 수 있습니다.

### 방법 3: 저장소 복제 후 심볼릭 링크 생성

소스를 읽거나 수정하려는 경우에 적합합니다. 아래는 Claude Code에 등록하는 예시입니다.

```bash
git clone https://github.com/addsumtech/job-hunt.git
cd job-hunt
mkdir -p ~/.claude/skills
ln -s "$PWD" ~/.claude/skills/job-hunt
```

Codex에서는 마지막 두 줄의 `~/.claude/skills`를 `~/.codex/skills`로 바꿉니다. 대상 경로가 이미 존재하면 기존 설치를 먼저 확인하세요.

### 의존성 설치와 환경 점검

설치된 **job-hunt 루트 디렉터리**(`SKILL.md`와 `requirements.txt`가 있는 위치)로 이동한 뒤 Python 3.10+ 환경에서 실행합니다.

먼저 `python3 --version`으로 3.10 이상인지 확인하세요. 이전 버전이면 Python 3.10+를 설치하고 해당 명령(예: `python3.12`)으로 아래 가상 환경을 만드세요.

```bash
python3 -m venv ~/.venvs/job-hunt
source ~/.venvs/job-hunt/bin/activate
python3 -m pip install -r requirements.txt
python3 scripts/doctor.py
```

위 활성화 명령은 macOS/Linux용입니다. Windows에서는 가상 환경의 `Scripts` 디렉터리에 있는 활성화 스크립트를 사용합니다. 에이전트도 프로젝트 스크립트를 실행할 때 이 Python 환경을 사용하도록 하세요. 기본 패키지는 `PyYAML`과 `python-docx`입니다. `doctor.py --install`은 현재 Python 환경에 없는 패키지를 설치할 수 있습니다.

| 기능 | 추가 의존성 | 없을 때의 영향 |
|---|---|---|
| 이력서와 지원 동기서 PDF | LaTeX 엔진. `tectonic` 권장 | Markdown, Word, 나중에 컴파일할 `.tex`는 생성 가능 |
| Markdown 보고서의 PDF 변환 | `pandoc`와 LaTeX 엔진 | 다운로드 폴더의 보고서가 Markdown만 제공될 수 있음 |
| PDF 텍스트 추출과 검사 | Poppler의 `pdftotext` | PDF에 텍스트가 온전히 보존됐는지 완전히 검증할 수 없음 |
| 실시간 공고 검색 | `opencli`와 해당 브라우저 환경 | 붙여 넣은 공고로 평가, 서류 준비, 모의 면접을 계속할 수 있음 |
| 중국어·일본어·한국어 PDF | 출력 언어에 맞는 글꼴 | 안정적인 조판을 위해 해당 글꼴 설치 필요 |

`doctor.py`는 실제 PDF 생성을 시도하고 부족한 기능을 알려 줍니다. `--install`은 Python 패키지만 설치하며, 시스템 도구는 보고서의 안내에 따라 설치합니다.

### OpenCLI Chrome 확장 프로그램 설정

**실시간 공고 조회에는 OpenCLI CLI와 Browser Bridge 확장 프로그램이 모두 필요합니다. 확장 프로그램은 Chrome에서 직접 설치해야 합니다.** `npm install`이나 `doctor.py --install`로는 확장 프로그램이 설치되지 않습니다.

1. **CLI를 설치합니다.** 터미널에서 실행하세요.

   ```bash
   npm install -g @jackwener/opencli
   opencli doctor
   ```

   확장 프로그램 설치 전에는 연결되지 않았다고 표시되어도 정상입니다.

2. **확장 프로그램을 다운로드하고 압축을 풉니다.** [OpenCLI 공식 Releases](https://github.com/jackwener/opencli/releases)의 Assets에서 `opencli-extension-v*.zip`을 받으세요. `Source code`는 아닙니다. 계속 보관할 위치에 압축을 풀고, `manifest.json`이 바로 들어 있는 폴더를 찾으세요.
3. **Chrome에 로드합니다.** 주소창에 `chrome://extensions/`를 입력하고 **개발자 모드**를 켠 뒤 **압축해제된 확장 프로그램을 로드합니다**를 클릭하여 위 폴더를 선택하세요. ZIP이나 `manifest.json` 파일 자체가 아닌 폴더를 선택합니다. Chrome에 표시되는 권한도 확인하세요.
4. **연결을 확인합니다.** Chrome을 열어 둔 채 `opencli doctor`를 다시 실행하세요. **Extension: connected**와 **Connectivity: connected**를 확인합니다. CLI나 daemon만 정상이면 아직 연결이 완료된 것이 아닙니다. 확장 프로그램 폴더는 옮기거나 삭제하지 마세요.

| 문제 | 해결 방법 |
|---|---|
| 파일 선택 창에서 폴더가 보이지 않음 | macOS에서는 `Command + Shift + G`를 누르고 전체 경로를 붙여 넣으세요. `.`으로 시작하는 폴더는 기본적으로 숨겨집니다 |
| 매니페스트 파일을 찾을 수 없음 | `manifest.json`이 바로 들어 있는 폴더를 다시 선택하세요. 압축 해제 폴더 안의 하위 폴더일 수 있습니다 |
| 확장 프로그램을 로드했지만 연결되지 않음 | 현재 Chrome 프로필에서 활성화되어 있는지 확인한 뒤 `opencli doctor`를 다시 실행하세요 |

채용 사이트 로그인이 필요하면 브라우저에서 직접 진행하세요. 확장 프로그램 연결은 브라우저와 연결되었다는 뜻이며, 각 사이트의 조회 가능 여부는 따로 확인해야 합니다.


## 지역, 플랫폼, 언어

공고 탐색은 `opencli` 어댑터를 통해 이루어집니다. 저장소의 출처 목록에는 51job, Indeed, LinkedIn, BOSS 直聘 등이 있으며 로그인 요건, 채용 공고, 면접 후기 출처를 구분합니다. 실제 접근 가능 여부는 실행 시점에 확인합니다. Indeed 어댑터는 미국 사이트에 연결되며 국가별 사이트 전환을 지원하지 않습니다. 다른 국가의 공고는 현지 출처를 우선 사용하세요. [출처 목록](references/discovery-sources.md)과 [출처 이용 규칙](references/source-policy.md)(영어)을 참고하세요.

중국 시장에서는 대형 민간기업, 중소 민간기업, 국유기업, 외국계 기업 등의 선호도도 확인합니다. 이는 정렬에 반영되며 다른 유형을 몰래 제외하지 않습니다. 牛客와 一亩三分地는 면접 후기와 채용 절차 참고용이며, 게시판 글을 채용 공고 목록에 넣지 않습니다.

로그인이나 사람 확인이 필요하면 이유와 브라우저에서 할 일을 안내하고 해당 사이트 조회를 일시 중지합니다. “완료했으니 계속해”라고 답하면 이전 기록을 보존한 채 횟수가 제한된 새 조회를 시작해 접근이 복구되었는지 확인합니다. 요청 제한과 권한 문제는 별도로 설명합니다. 계속 접근할 수 없다면 다른 출처를 선택하거나 공고 본문을 붙여 넣거나 이미 가져온 결과를 확인할 수 있습니다. 공고 탐색은 읽기 전용이며 메시지 전송, 온라인 프로필 수정, 자동 지원을 하지 않습니다.

**지원 지역의 규칙과 출력 언어는 별도로 처리합니다.** 이력서 렌더러에는 영어, 네덜란드어, 독일어, 프랑스어, 스페인어, 이탈리아어, 중국어, 일본어, 한국어의 제목과 개인정보 항목명이 포함되어 있습니다. `discover`와 `assess`의 집계 카드, 필수 제목과 설명은 중국어, 영어, 일본어, 한국어, 스페인어의 [보고서 언어 템플릿](references/report-localization.md)으로 생성하고 검증합니다. 내부 문서, 진단 메시지, 출처가 있는 지역 관행 카드에는 아직 번역되지 않은 부분이 있습니다. PDF에는 출력 언어에 맞는 글꼴도 필요합니다.

미국, 영국, 독일, 네덜란드, 중국의 **시장 관행 표 5개에 총 38개 항목**이 있으며 출처와 재검토 기한이 기록되어 있습니다. 기한이 지난 항목에는 표시를 하고, 해당 시장 데이터가 없을 때도 알립니다. 각 항목의 적용 범위에 맞춰 참고할 수 있는 배경 정보입니다.

  <img src="docs/assets/personal-data.jpg" alt="저장소 렌더링 예시: 미국 지원용 이력서는 개인정보를 생략하고 독일 지원용은 제공된 사진과 생년월일을 표시">
</p>

개인정보는 지원 지역 규칙에 따라 처리합니다. 미국, 캐나다, 영국, 아일랜드, 호주, 뉴질랜드용 일반 이력서에서는 렌더러가 사진과 `contact.personal` 항목을 표시하지 않고, 워크플로가 처리 내용을 설명합니다. 지역을 인식하지 못한 경우에도 기본적으로 생략합니다. 다른 인식 가능한 지역에서는 규칙에 따라 제공된 정보를 표시할 수 있습니다. 위 이미지는 렌더러의 동작 예시이며, 한 국가의 모든 고용주가 같은 형식을 요구한다는 뜻은 아닙니다.

## 받을 수 있는 결과물

| 자료 | 형식과 설명 |
|---|---|
| 맞춤 이력서 | Markdown, Word(`.docx`), PDF. PDF 조판 소스 `.tex`도 보존 |
| 커버레터·지원 동기서 | 필요할 때 생성하며 Markdown, Word, PDF 지원 |
| 일본식 이력서(履歴書) | 별도 양식 렌더러로 Markdown 미리 보기와 편집 가능한 `.docx` 생성. 양식 PDF는 Word 또는 LibreOffice에서 내보내기 |
| 항목별 지원 설명서 | NHS와 영국 공무원 등의 지원에 맞춰 요건별 근거를 정리하고 단어 수 제한 검사 |
| 평가와 면접 자료 | 공고 후보 목록, 적합성 평가, 면접 준비 자료, 모의 면접 기록과 피드백 |

항목별 평가 방식의 지원에서는 고용주 기준에 따라 supporting statement를 검토합니다. 일반 이력서도 필요하면 별도로 세 검토자의 심사를 진행합니다. 일본식 이력서는 양식의 완전성을 확인하며, 함께 제출하는 경력기술서 등은 일반 이력서 절차에 따라 검토합니다.

각 회차의 읽을 수 있는 결과물은 기본적으로 `~/Downloads`에 저장합니다. 예를 들면 `<company>-<role>-<date>-cv.md`와 해당 PDF입니다. PDF 생성과 검증은 도구 환경에 따라 달라지며, 전달 결과에 누락된 파일이나 완료하지 못한 검사를 표시합니다.

## 파일 저장 위치

원본 프로필, 지원별 작업 공간, 검사 기록은 기본적으로 `~/.claude/job-profiles/`에 저장하며 Codex에서도 같은 위치를 사용합니다. 다른 루트 디렉터리는 `JOBHUNT_PROFILES_ROOT`로 지정할 수 있습니다.

한 사람의 원본 프로필을 `profile.zh.yaml`, `profile.en.yaml`처럼 언어별로 보관할 수 있고 기존 `profile.yaml`도 지원합니다. 지원 건별로 작업 공간을 분리하며 출처 기록과 `journal.jsonl`에 검사 이력을 남깁니다. 전체 구조는 [REFERENCE.md](REFERENCE.md)(영어)를 참고하세요.

파일은 로컬에 저장됩니다. 모델 호출과 웹 접근은 사용하는 에이전트 및 서비스 설정에 따라 이루어집니다.

## 검증과 참고 자료

자동 검사는 근거 참조, 원본 프로필 보호, 검토 결과 파싱, 개인정보 처리, 조판, 모드 간 전환 등을 다룹니다.

```bash
python3 -m pip install pytest
make check
make eval-lint
```

`make check`는 Python 테스트, 마이그레이션 내용 보존 검사, 시장 관행 표 검사를 실행합니다. 일부 테스트는 해당 컴퓨터의 Skill 설치 상태와 외부 도구를 확인하므로 실행 환경을 고려해 결과를 읽어야 합니다. **검사를 통과해도 결과물의 정확성이 보장되지는 않습니다**. 취업 성과를 입증하는 것도 아닙니다.

[`evals/`](evals/README.md)에는 20개의 행동 평가 시나리오가 있습니다. 기록된 2차 평가(2026-09-05/06)는 15개 시나리오를 Skill 사용·미사용으로 짝지어 실행했습니다. 두 그룹의 차이를 확인하는 검사 10개가 기준 실행의 `FAIL`에서 Skill 사용 시 `PASS`로 바뀌었습니다. **각 시나리오·각 그룹당 한 번 실행했으며 n = 1**입니다. 안정적인 성공률이나 채용 결과 예측을 뜻하지 않습니다. 미실행 검사와 무효로 처리된 시나리오 결과도 [평가 기록](evals/iterations/iteration-2-with-skill.md)에 포함되어 있습니다.

저장소에는 2026-09-06에 `codex exec`로 세 이력서 검토자를 실행한 검증도 기록되어 있습니다. 호스트별 실행 방식과 검증 범위는 [다른 에이전트에서 사용하기](references/portability.md)를 참고하세요. 테스트하지 않은 호스트를 검증된 연동으로 표기하지 않습니다.
